2D PHYSICS ENGINE: CAMERA SYSTEM ANALYSIS

1. HOW THE CURRENT CAMERA WORKS

The camera (simple_camera) acts as the bridge between the World Space (where the physics engine simulates bodies using meters) and the Screen Space (where SDL2 draws pixels). 

Because the engine does not yet use matrix transformations, it relies on direct algebraic formulas to map points back and forth.

1.1 World-to-Screen Formula (Rendering)
When the engine needs to draw a physics body, it must calculate where a world coordinate appears on your monitor.

The formula used in RenderPhysicsBody is:
Screen_X = (World_X - Camera_X) * Zoom + (ScreenWidth / 2)
Screen_Y = (World_Y - Camera_Y) * Zoom + (ScreenHeight / 2)

How it works:
- (World_X - Camera_X): Finds the object's position relative to the camera's center in world space.
- * Zoom: Scales that relative distance. If zoomed in (> 1.0), the distance from the center grows. If zoomed out (< 1.0), the distance shrinks.
- + (ScreenWidth / 2): Shifts the origin (0,0) from the top-left of the monitor to the exact center of the screen.

1.2 Screen-to-World Formula (Mouse Input)
When the user clicks the screen, the engine must reverse the above formula to figure out what world coordinate they clicked.

World_X = Camera_X + ((Screen_X - (ScreenWidth / 2)) / Zoom)
World_Y = Camera_Y + ((Screen_Y - (ScreenHeight / 2)) / Zoom)

How it works:
- Screen_X - (ScreenWidth / 2): Finds the cursor's distance from the center of the screen in pixels.
- / Zoom: Un-scales those pixels back into world units (meters).
- + Camera_X: Offsets the result by the camera's actual location in the world.

1.3 The Zoom Formula (Zoom-to-Mouse)
A standard zoom just multiplies the Zoom variable, which zooms into the center of the screen. A high-quality camera zooms into the cursor's location.

The Algorithm:
- Calculate the World position of the mouse cursor before the zoom changes (WorldBefore).
- Apply the zoom multiplier (Zoom *= 1.1f).
- Calculate what the Camera's Position should be so that WorldBefore stays under the exact same screen pixel after the zoom:
  Camera_X = WorldBefore_X - (MouseOffsetX / NewZoom)

1.4 The Pan Formula
When dragging the camera, the mouse moves by a delta pixel amount (DeltaX, DeltaY).
To make the mouse stick perfectly to the ground it grabbed, the camera's world position moves by the delta, un-scaled by the zoom:
Camera_X = Camera_X - (DeltaX / Zoom)

2. FUTURE IMPROVEMENT PLANS

- Transformation Matrices: Replace the manual algebraic formulas with standard 3x3 Matrices (Translation, Rotation, Scale). This offloads math to standard linear algebra and decouples rendering from camera logic.
- Advanced Frustum Culling: Upgrade the IsVisible AABB check to properly cull rotated bodies using SAT against the camera's view polygon.
- Camera Rotation: Allow the camera to tilt/rotate.
- Interpolation (Lerp/Springs): Smooth out the discrete zooming and panning using delta time and Hooke's Law (springs) for a premium feel.
- Zoom Constraints: Clamp the Zoom variable (MinZoom, MaxZoom) to prevent floating-point precision loss or divide-by-zero crashes.

--------------------------------------------------

3. RESOURCES TO IMPROVE CAMERA KNOWLEDGE

To implement the improvements above, check out these excellent resources on 2D Cameras and Math:

Matrices & Coordinate Systems:
- LearnOpenGL - Transformations (learnopengl.com/Getting-started/Transformations): The definitive guide to understanding how Translation, Rotation, and Scaling matrices work. Even though it's 3D/OpenGL focused, the exact same math applies to 2D using 3x3 matrices.
- LearnOpenGL - Camera (learnopengl.com/Getting-started/Camera): Explains the "View Matrix" concept, which is what your simple_camera will eventually become.

Camera Feel & Juice (Interpolation / Springs):
- Math for Game Programmers: Building a Better Jump (youtube.com/watch?v=hG9SzQclR2b): A GDC talk that explains how to use springs, lerp, and damping for movement. This math is exactly what you apply to a camera to make panning/zooming feel smooth and cinematic.
- Scroll Back: The Theory and Practice of Cameras in Side-Scrollers (gamedeveloper.com/design/scroll-back-the-theory-and-practice-of-cameras-in-side-scrollers): An iconic article on 2D camera logic, tracking windows, deadzones, and lerping. 

Advanced 2D Frustum Culling:
- 2D Visibility/Frustum Culling (gamedev.stackexchange.com/questions/112635/how-to-do-2d-frustum-culling-with-a-rotated-camera): A great thread detailing how to check if a rotated 2D object is inside a rotated 2D camera view using SAT or AABB hierarchies.
